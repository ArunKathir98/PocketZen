11 · The UI layer

11.1 Styling system (styles.css)

  • Design tokens as CSS custom properties on :root, taken from the logo's mint-to-teal gradient: --g1 #8fe69a, --g2 #1ccbb0, --g3 #03a7c3, --grad, plus --ink, --muted, --surface, --line, --income, --expense.
  • Dark mode: :root[data-theme='dark'] overrides the tokens. The attribute is set before paint by the inline script in index.html, and changed by applyTheme() in User.jsx (light / dark / auto follows the OS).
  • No component library: a small vocabulary of classes — .card, .list/.item, .btn (.primary .ghost .danger .sm), .chip, .seg (segmented control), .field/.input, .hero, .banner, .bar, .toggle.
  • Sizes were tuned for real screens: 14 px base text, 34 px icon buttons, 52 px floating button, compact lists. A visual pass on 390×844 and 1440×900 screenshots caught overlaps and oversized controls.
  • Text selection is disabled app-wide (user-select: none) for an app-like feel; inputs, textareas, selects and elements with .selectable (recovery code, group id) stay selectable.

11.3 Modals and dialogs

  • Modal (ui.jsx): bottom sheet on phones, centred card on desktop. A module-level stack ensures that when several modals are open (person → loan → payment form) only the topmost reacts to Escape, and body scrolling stays locked until the last one closes. The callback is kept in a ref so the effect registers once and ordering never gets scrambled by re-renders.
  • Stacking order is simply DOM order. A page that opens a form from inside another modal must render that form after the parent modal. (A real bug: "Add loan" opened behind the person screen until the render order was swapped.)
  • Dialogs (dialog.jsx) are promise-based and sit above modals (z-index 120).

11.5 Accessibility basics included

  • Icon-only buttons have aria-label; toggles are role="switch" with aria-checked; modals have role="dialog" and aria-modal; dialogs use role="alertdialog".
  • Visible focus rings (:focus-visible), prefers-reduced-motion disables animations, colour is never the only signal (labels like "owes/gets/over by").
  • The PIN pad also accepts the physical keyboard.

11.6 Adding a page — the recipe

  1. Create src/pages/MyPage.jsx; read data with useApp(), mutate with add/update/remove.
  2. Put calculations in a pure src/lib/mything.js and unit-test them.
  3. Add the new collection to emptyData(), to the array list in normalize() (store.jsx), and to mergeData (merge.js) — otherwise import/merge/sync will silently drop it.
  4. Add a row to TABS in App.jsx (with a settings flag if it is optional) and a toggle in User.jsx; add it to LITE_TABS only if lite users should have it.
