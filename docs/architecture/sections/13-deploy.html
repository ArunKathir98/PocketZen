13.2 Environment variables

VariablePurpose
VITE_GOOGLE_CLIENT_IDOAuth web client id (sign-in).
VITE_GOOGLE_API_KEYBrowser API key, restricted to the site and the Drive API. Enables group view links (optional).
Vite replaces import.meta.env.VITE_* with literal text at build time. On Cloudflare they must be build variables, and the site must be rebuilt after changing them. A runtime Worker variable has no effect on the bundle.

13.3 Google Cloud checklist

  1. Create a project; enable the Google Drive API.
  2. Google Auth Platform: name, support email, home page /home.html, privacy policy /privacy.html; Data Access scopes openid, email, profile, drive.appdata, drive.file; publish to Production (no review needed for these scopes).
  3. OAuth client (Web): authorised JavaScript origins = http://localhost:5173 + the production origin (no trailing slash).
  4. API key: Websites restriction (https://<domain>/*, http://localhost:5173/*) and API restriction = Drive API.
Consent screen name. Google shows the app name and logo only after brand verification, which needs a domain you own. On a shared workers.dev address the consent screen shows the address instead. A custom domain is the way to get "Sign in to PocketZen".

Why Workers static assets and not Pages? Cloudflare is steering new projects to Workers; it is free for static sites, has global CDN, and the same config can later grow API routes. The tiny worker/index.js exists only so the migration history (which retires an old Durable Object) can be applied.

13.5 Static pages for Google's consent screen

public/home.html (what the app is) and public/privacy.html (privacy policy) are plain HTML files copied to the site root. Google requires both URLs to publish an OAuth app. They are deliberately not React: crawlers read them without running JavaScript.

13.6 Release checklist

  1. npm run build succeeds locally.
  2. Smoke test the preview build: sign in, add a record, reload, check the status pill says "Synced to Drive".
  3. Push to main; watch the Cloudflare deploy log.
  4. Open the live URL in a private window; reload twice (service-worker update).
  5. If environment variables changed, confirm they are build variables and redeploy.
