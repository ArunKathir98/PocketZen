9 · Feature modules

Each feature follows the same pattern: a page (UI) + a pure module (rules) + data in the document (changed only through useApp()).

9.1 Records and the Add sheet

  • Page: Records.jsx. State: mode (day/week/month) and cursor (a Date). calc.periodRange(mode, cursor) returns inclusive {from,to} date strings; summarize() gives income / expense / net; groupByDay() builds the grouped list. Weeks start on Monday.
  • Form: AddSheet.jsx handles income, expense and transfer in one modal. Transfers need two different accounts and no category.
  • Budget hint: for an expense in a budgeted category it shows left = budget − spent this month (excluding the record being edited) and what remains after the typed amount (calc.monthSpentByCategory).
  • Dates are 'YYYY-MM-DD' strings and times 'HH:mm'; sorting is plain string comparison.

9.2 Categories, Accounts, Budget

  • Categories: add/edit/delete with emoji + colour. Deleting a used category is allowed: its records show as "Uncategorized" and its budget is removed. Tapping a category opens CategoryDetail (all its transactions, Monthly/Weekly/Daily/All filter, budget bar).
  • Accounts: balance is computed (accountBalance), never stored. An account with records cannot be deleted (the dialog says why).
  • Budget: one monthly limit per expense category; the page sums that month's expenses per category and shows progress (amber from 80 %, red over 100 %).

9.3 EMIs (emi.js, Emi.jsx)

paidCount  = paidBefore + payments.length
paidAmount = paidBefore × emiAmount + Σ payments.amount
pending    = max(0, totalMonths − paidCount)
remaining  = max(0, totalAmount − paidAmount)
nextDue    = addMonths(startDate, paidCount)       // month-end safe: Jan 31 → Feb 28
nextAmount = pending === 1 ? remaining : emiAmount // the last instalment clears rounding leftovers

"Pay EMI" records a payment and, if an account is chosen, also adds an expense under an auto-created "EMI & Loans" category (the payment keeps the txId, so "Undo last" removes both). Completed EMIs move to their own tab.

9.4 Loans and people (loans.js, Loans.jsx)

A loan belongs to a person and has a direction (lent = they owe you, borrowed = you owe them). Its entire state is a list of dated events; every number on screen is derived from them by loanStats(loan, asOf).

Event kindEffect
principalMoney given/taken (the first one is the opening amount; later ones are top-ups).
payment{ amount, principalPart, interestPart } — the split is chosen by the user ("interest first" by default via suggestSplit).
interestA manual interest charge.
termsInterest rate / fixed amount changes from this date onward.
Interest typeHow it accrues
none—
fixedThe fixed amount is added on every monthly anniversary of the start date while principal is outstanding.
simpleP × monthlyRate × (wholeMonths + days/30) per segment, where monthlyRate = rate/100 (per month) or rate/100/12 (per year).
compoundLike simple, but each whole month uses (P + unpaidInterest) × monthlyRate; the part-month remainder is pro-rated.
manualNothing automatic; the user adds interest events.

The engine sorts events by date, walks them in order, and before applying each event "advances" accrual from the previous date to that date. Rate changes and repayments therefore split the timeline into segments. Outputs: principal in/paid/balance, interest charged/paid/due, outstanding = principal + max(0, interestDue), settled, nextInterestOn. personSummary() adds a person's loans (receivable minus payable) and buildStatement() creates the WhatsApp-ready text.

Why events instead of storing balances? A history of events can be edited (delete a wrong payment) and every figure is recalculated correctly. Stored balances would need manual repair after any correction. Verified numbers: ₹10 000 at 2 %/month for 3 months → ₹600; 12 %/year on ₹12 000 for 6 months → ₹720; compound 2 %/month for 3 months → ₹612.08.

Optionally an entry is also recorded as a normal income/expense in an account (categories "Money lent", "Money borrowed", "Loan repayment received/paid"); the event stores the txId so deleting the entry removes that record too.

9.5 Reminders and notifications (reminders.js, notify.js)

  • Recurrence: occurrence(r, n) returns the n-th due date (daily +n days, weekly +7n, monthly +n months clamped to month length). nextOccurrence(r) uses doneCount ("Mark done" increments it) and honours until.
  • checkDue(data) (called every 30 s while the app runs) fires: due bill reminders; loan interest days (09:00, the loan's start day each month) and repay-by dates; and the daily expense nudge (skipped if a record already exists today). A "fired" map in localStorage['pz:fired'] makes each reminder fire once.
  • fireReminder(): if the app is visible → in-app toast + chime (Web Audio) + vibration; if hidden → a system notification through the service worker (registration.showNotification, so tapping it re-opens the app).
Hard platform limits: a website cannot schedule an alert for a phone that is locked or has the app fully closed (that needs a push server), and it cannot choose the system notification sound. The UI states this plainly; the sound/vibration toggle controls the in-app chime and whether the notification is "silent".

9.6 Backup, restore and the lite mode

  • Backup (BackupModal): optional password; shares via the share sheet or downloads; records settings.lastBackupAt. Local-only users get a BackupBanner after 14 days (snoozable for 3).
  • Import: reads the file, asks for a password if encrypted, then Replace all or Merge (mergeData).
  • Lite mode: App.jsx filters the tab list to four pages, User.jsx hides notification/page settings, reminders don't run. Everything else is shared code, which is why upgrading to Google later is just a data move (7.7).

9.7 Profile page structure (User.jsx)

Sections in order: profile card → Backup & sync (CloudCard) → Appearance (theme, stored in pz:theme) → Preferences (currency, daily reminder) → Notifications → Pages (optional-page toggles) → Security (PIN) → Your data (export/import) → Share & feedback → Log out / Erase. Google-only sections are hidden in lite mode.
