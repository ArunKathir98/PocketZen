14 · Testing approach

The repository has no test runner configured yet. During development, correctness was checked with throw-away scripts in two layers. Describing them here so you can reproduce or formalise them.

14.1 Layer 1 — pure-logic tests (Node)

Because the domain modules are plain functions, they can be bundled (the project's own Rolldown, since the source uses extension-less imports) and exercised with node:assert.

ModuleWhat was asserted
merge, backup, pinSame-named accounts/categories unify; ids remapped; PIN excluded from backups; encrypted backup hides content, wrong password rejected; recovery code format and forgiving input.
loansNone/fixed/simple (monthly and yearly)/compound/manual; mid-way rate change; partial month (45 days); top-ups; repayments; fixed interest stops when principal is cleared; settled detection; person totals; statement text.
reminders + merge of loansInterest-day and repay-by reminders fire once, not before 09:00, not for settled loans or when the page is off; people/loans merge with remapping.
groupStateSplits always sum to the total (also for 7 people, odd cents); balances sum to 0; settle-up ≤ n−1 transfers and clears everyone (80 random expenses); last-write-wins, idempotent replay, deletes, validation rejects bad input without mutating, limits, group-link parsing.

14.2 Layer 2 — end-to-end tests (Playwright + mocked Google)

A headless Chrome/Edge runs the production build. Network calls to Google are intercepted with page.route, and a small in-memory fake Drive implements exactly the rules the app depends on (owner's token for edits, public read only with a key and only when shared, app-data per user, delete). The Google script is replaced by a stub that counts requestAccessToken() calls.

14.3 What the tests caught (examples)

  • Data loss on refresh — reproduced with two devices (7.4) before fixing.
  • A logout button without confirmation — an un-awaited dialog promise.
  • A form opening behind another modal — DOM-order stacking.
  • A sync pill stretching to full height — a CSS class name (.auth) reused for two unrelated things.
  • New device can't open a group — the "Allow" prompt was drawn on a screen that only appears once the group has loaded.

14.4 Recommended next step

Move these into the repository: add Vitest for the pure modules (src/lib/*.js) and @playwright/test for the flows, with the fake-Drive helper as a shared fixture, and run both in CI before deploy. The logic modules are already structured for this: no changes to production code are needed.
