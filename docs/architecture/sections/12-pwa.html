12.2 Service worker details

VitePWA({
  registerType: 'autoUpdate',
  workbox: {
    importScripts: ['sw-notify.js'],          // our own handlers, loaded into the generated worker
    globPatterns: ['**/*.{js,css,html,png,svg,ico}'],
    navigateFallback: '/index.html',          // SPA: any navigation serves the app shell …
    navigateFallbackDenylist: [/^\/privacy\.html$/, /^\/home\.html$/],  // … except these pages
  },
})
  • public/sw-notify.js adds notificationclick (focus an open window or open the app) and a push handler (ready for a future push server; unused today).
  • The denylist matters: without it the service worker would answer /privacy.html with the app instead of the policy page (the pages Google's consent screen links to).
  • Drive and Google requests are cross-origin fetch calls and are never cached by the service worker.
Updating: because the app shell is precached, a user sees a new deploy on the next load after the new worker activates. If a fix "doesn't show", reload twice or clear site data.

12.3 The install prompt (install.js, InstallBanner)

  • Android / desktop Chrome: a module-level listener stores the beforeinstallprompt event as soon as the page loads (before React mounts). The banner's Install button calls event.prompt().
  • iPhone Safari fires no such event, so the banner shows the manual steps (Share → Add to Home Screen).
  • Hidden when already standalone (display-mode: standalone or navigator.standalone) and for 7 days after dismissal (pz:installDismissed). It also appears on the login page.

12.4 Notifications pipeline

StepCode
Ask permissionaskNotificationPermission() — never on page load (browsers block that). It is requested when the user enables reminders or taps Allow in NotifyBanner / the Profile card.
Decide when to firecheckDue() every 30 s and when the tab becomes visible (chapter 9.5).
ForegroundChime (Web Audio, three sine tones) + vibration + in-app toast. Audio is unlocked by the first tap (unlockAudio in main.jsx).
Background tab / installed appsystemNotify() → navigator.serviceWorker.ready → registration.showNotification(title, { body, tag, vibrate, requireInteraction, data }). If sound is off the notification is silent: true (the spec forbids combining silent and vibrate).
Tap on notificationnotificationclick in sw-notify.js focuses or opens the app.
Why no push server? It would be the only server in the project and would hold users' reminder text. We accepted the limit that alerts depend on the app being able to run, and documented it. The service worker already contains the push handler, so adding a push backend later would be additive.
