15 · Step-by-step implementation

This is the order the app was actually built in, written so you can follow it to build the same thing. Each step says what to do, which files are involved and why it comes at that point.

1

Scaffold, brand and PWA shell

Do: npm i react react-dom lucide-react, dev deps vite @vitejs/plugin-react vite-plugin-pwa sharp. Turn the logo into a transparent PNG and the icon set with scripts/make-icons.mjs. Define colour tokens in styles.css from the logo gradient; write the inline theme script in index.html. Configure the PWA plugin (manifest + Workbox).
Why first: a consistent theme and an installable shell make every later screen look right from day one.

2

Data model and local store

Do: write defaults.js (emptyData()), then store.jsx with commit, add/update/remove, persisted to localStorage at first (moved to IndexedDB in step 11). Add util.js (ids, dates, money) and calc.js (balances, periods).
Why: every page depends on the document shape. Fix it early and keep it a single JSON object.

3

Core pages

Do: Records + AddSheet, Categories, Accounts, Budget, Reminders, Profile; shared Modal/Toggle/Empty in ui.jsx; bottom-nav/sidebar in App.jsx.
Why: proves the store API (add/update/remove) is enough for real screens before adding networking.

4

Google sign-in and Drive sync

Do: create the Google Cloud project and OAuth client; load GIS in index.html; write google.js (requestToken, fetchProfile, driveLoad, driveSave); add login, pull, push, schedulePush, dirty flag to the store; build Login.jsx.
Why now: the local-first store already works, so sync is "just" mirroring one document.

5

PIN lock and keep-signed-in

Do: pin.js (PBKDF2), PinPad, PinLock, auto-lock on hidden ≥ 60 s; session never expires. First "Forgot PIN" emailed a code through Gmail, later replaced by Google re-verification (chapter 8.6).
Why: it needs both the store and auth, so it comes after step 4.

6

OAuth publication requirements

Do: add public/home.html and privacy.html, branding, remove sensitive scopes so no verification is needed.
Lesson: request the smallest scopes you can. One sensitive scope would have blocked publishing.

7

Polish pass for real screens

Do: shrink type/controls, fix overlaps, screenshot at phone and desktop sizes; replace browser confirm with DialogProvider.
Why: a first design is usually too big on phones; checking screenshots catches layout bugs a linter cannot.

8

Optional pages: EMIs, category details

Do: emi.js + Emi.jsx; CategoryDetail; feature flags (showEmi, showReminders) with toggles in Profile; TABS gets a 5th "flag" element.
Why flags: a simple app stays simple; power features are opt-in.

9

Notifications, install prompt, sharing

Do: notify.js, sw-notify.js, install.js, banners, NotificationsCard; share card with WhatsApp text and poster; feedback form link in config.js; poster generator.
Lesson: browsers can't ask for notification permission on load, can't pick a sound, and can't alert a locked phone; design the UI honestly around that.

10

Local-only mode, backups, recovery code

Do: idb.js and move the store to IndexedDB (with one-time migration); loginLocal; backup.js (AES-GCM) + BackupModal; recovery code in pin.js; CloudCard + switchToGoogle/disconnectGoogle; merge.js.
Why: having a clean "session mode" in the store made this additive rather than a rewrite.

11

Loans & people

Do: design the event model first, write loans.js and its tests (the maths must be right before any UI), then Loans.jsx, reminders for interest days, optional account recording, statements.
Why events: any correction stays consistent (chapter 9.4).

12

Lite mode gating

Do: LITE_TABS in App.jsx, hide Google-only settings in User.jsx, skip the reminder scheduler for local sessions.
Why: the product decision was "no account = simple tracker; Google = full app"; one set filter implements it.

13

Groups: server prototype → Drive-hosted

Do (final design): groupState.js (ops, LWW, splits, balances, settle-up), useGroup.js (cache, polling, outbox), group file functions in google.js, Groups.jsx, GroupView.jsx, PublicGroup.jsx, groupPdf.js, pendingJoin.js.
Lesson: the server version worked, but it contradicted the product's promise; choosing the simpler "admin edits, others view" model deleted the hardest problem (concurrent writers) and the server with it.

14

Hardening from real-use bug reports

Do: (a) read-merge-write on push + re-check Drive on foreground → no more overwritten data; (b) cache the token + forbid background sign-in windows; (c) sharing switch + clear API-key error messages; (d) remove unused code; (e) update README, privacy policy, home page, poster.
Lesson: every item here was found by a user or by a reproducing test — write the failing test first, then fix.

15.1 "If I had to rebuild it in a weekend" checklist

  1. Vite + React + PWA plugin; tokens and theme.
  2. emptyData(), store.jsx with commit and IndexedDB.
  3. Records, Categories, Accounts pages with one reusable Modal.
  4. Local-only session + backup file. You already have a useful app here.
  5. Add Google token flow, driveLoad/driveSave, push/pull with dirty flag.
  6. Add read-merge-write and the token cache immediately (don't repeat our bugs).
  7. PIN lock; notifications; optional pages one at a time, each with a pure module and tests.
  8. Groups last, as Drive files with an admin and view-only links.
